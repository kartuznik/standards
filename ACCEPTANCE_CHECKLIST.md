# Product Acceptance Checklist (end-to-end)

Обязательный чек-лист продуктовой приёмки **перед продажей / демо покупателю**.
Живёт только в `/opt/standards`. Продуктовые репозитории не дублируют канон целиком — ссылаются на него.

Эталон прохождения: Watchdog Bot (после закрытия поискового контура).

Отмечай каждый пункт только после **живой** проверки (не «по коду»).

---

## 1. Честный визуал (Telegram / UI)

- [ ] Ответы без сырого markdown (`#`, `##`, «голые» `**` там, где ожидается HTML/чистый текст продукта).
- [ ] Нет технического мусора в пользовательских сообщениях (stack traces, JSON reviewer, внутренние stage-ключи).
- [ ] Длинные ответы чанкаются по границам предложений/абзацев; есть понятные маркеры продолжения при необходимости.
- [ ] Превью ссылок / Instant View не ломают читаемость (где применимо — отключены).

## 2. Источники

- [ ] Источники кликабельны: HTML-якоря и/или inline-кнопки.
- [ ] Ссылки **глубокие** (на статью/материал), не автолинк на «голый» домен / главную сайта.
- [ ] Заголовки экранированы; URL в `href` корректны.
- [ ] Блок источников отделён от draft/summary и не дублирует сырые URL в тексте без нужды.

## 3. Query gate (анти-словарный мусор)

- [ ] Поисковый запрос во внешний API — полный смысл темы или валидная переформулировка со смысловыми токенами.
- [ ] Ведущие вопросительные слова не уводят выдачу в словари/переводчики (класс «какие/что/как …»).
- [ ] При срабатывании gate в логах есть WARNING и fallback на полный оригинал.

## 4. Relevance-фильтр источников

- [ ] Источники без пересечения значимых слов с запросом отбрасываются.
- [ ] В логах есть причина отсева по каждому дропу.
- [ ] В пользовательский блок sources не попадают Linguee/dictionary-like результаты на вопросительных запросах.

## 5. Recency-aware retrieval

- [ ] Маркеры актуальности (`сегодня`, `сейчас`, `последн`, `текущ`, `live`, `breaking`, …) включают freshness-путь на **retrieval**, не только в Reviewer.
- [ ] Поиск вызывается с news-topic + окном дней (дефолт **2**, конфигурируемо).
- [ ] Есть fallback (`start_date` / расширение окна) при пустой выдаче.
- [ ] Источники ранжируются по свежести; старше окна отбрасываются, если есть свежие.
- [ ] При деградации свежести — WARNING в логах.
- [ ] Логи содержат `tavily_days` (или аналог) и `source_date_range`.

## 6. Честная пометка даты данных

- [ ] Если запрос про «сегодня», а самый свежий источник старше окна — ответ **явно** указывает дату данных.
- [ ] Старые события не выдаются молча за текущие новости.
- [ ] При отсутствии цифр/фактов в evidence бот не выдумывает их из памяти модели.

## 7. Grounded generation

- [ ] Evidence (snippet + published_at) сохраняется и **immutable** после retrieval.
- [ ] Researcher / Writer / Summary опираются на evidence; parametric memory для фактов и дат запрещена промптом.
- [ ] Reviewer видит evidence и режет рассинхрон дат/фактов на freshness-запросах.
- [ ] Логи evidence_snippets / evidence_chars (или эквивалент) присутствуют.

## 8. RBAC и технический футер

- [ ] Технический футер (tokens / cost / iterations) виден только admin/owner (или принятой RBAC-модели продукта).
- [ ] Обычный user не видит внутреннюю экономику/диагностику в каждом ответе.

## 9. Экономика и observability

- [ ] Метрики cost и tokens экспортируются и видны в Prometheus/Grafana (или принятом стеке продукта).
- [ ] Usage/cost по пользователям доступны в admin soft-B2B пути (если заявлены в редакции).
- [ ] Router/fallback/queue (где есть) отражены на дашборде без «No data»-заглушек на нуле.

## 10. Алерты владельцу

- [ ] Алерты уходят владельцу в Telegram (Grafana contact point и/или in-bot health).
- [ ] Секреты алертов только через env (`$__env{…}`), не в YAML git.
- [ ] Базовые правила на ошибки / очередь / деградацию LLM (или продуктовые аналоги) заведены.

## 11. Документация и коммерческая гигиена

- [ ] Есть `docs/RUNBOOK.md` (deploy, backup, key rotation, incidents, rollback) **без** секретов и адресов сервера.
- [ ] README: честный scope (умеет / не умеет), архитектура Mermaid, Демо-плейсхолдеры, FAQ, ссылка на runbook, секция «AI-инструменты» после «Тестирование» и перед лицензированием (реально использованные инструменты или честная строка, что AI не использовался; выдуманные имена запрещены).
- [ ] Секция лицензирования: MIT + Community/Starter/Team/Custom по возможностям **без денежных цифр** в продуктовом git.
- [ ] Кросс-проектные каноны только в `/opt/standards` (камни отдельно, яйца отдельно).

## 12. Секреты и ops-закрытие

- [ ] В git нет `.env`, токенов, паролей admin/Grafana.
- [ ] Дефолтные пароли (`change-me`, `admin123` и аналоги) **не** используются на демо/продаже.
- [ ] Любое runtime-изменение закрыто: rebuild затронутых сервисов + **живой smoke агентом** до финального отчёта.
- [ ] После ручной правки `.env` — `grep` каждой изменённой строки **до** recreate; секреты в чат/скринах замаскированы; vault `CREDENTIALS.md` актуален.

## 13. Финальная приёмка в живом Telegram

- [ ] Финальная продуктовая приёмка подтверждена **живым сообщением в Telegram** (реальный диалог с ботом), а не только логами контейнеров, Prometheus/Grafana или unit/integration-тестами.
- [ ] На приёмочном запросе видны ожидаемые UX-эффекты (progress / format / sources / honesty note — по scope продукта).

---

## Мини-smoke (обязательный прогон перед продажей)

1. Креативный запрос без поиска — progress UX, нет Tavily-мусора.  
2. Фактологический «сегодня» — источники свежие **или** честная дата данных; нет словарных URL; нет выдуманных цифр.  
3. Admin login + Grafana login новыми (не дефолтными) паролями.  
4. Метрики cost/tokens / router видны; алерт-контакт настроен.

Подпись приёмки: продукт / дата / кто принял / git SHA.
