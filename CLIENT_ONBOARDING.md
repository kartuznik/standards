# CLIENT_ONBOARDING — Watchdog First Orders

Практический onboarding-плейбук для первых клиентских внедрений Watchdog Bot.
Основан на `watchdog_bot/docs/RUNBOOK.md` и текущем ТЗ Архитектора.

---

## 1) До заказа — вопросы клиенту (discovery checklist)

- [ ] У клиента уже есть VPS/сервер с Docker и Docker Compose (доступы подтверждены).
- [ ] Кто выпускает Telegram-токен в BotFather (ответственный и сроки).
- [ ] Какой LLM-провайдер используется на старте: OpenAI или DeepSeek (или оба для fallback).
- [ ] Есть ли рабочий Tavily API key для live web search.
- [ ] Согласованы основные сценарии использования (какие задачи должен решать бот).
- [ ] Получены реальные примеры вопросов от команды клиента (фактология, новости, аналитика).
- [ ] Уточнено, нужна ли редакция Team (выделенный сервер, админка, ops-алерты).
- [ ] Зафиксирован контакт владельца со стороны клиента для алертов и приемки.

---

## 2) Внедрение — запуск и приемка (implementation checklist)

- [ ] Деплой выполнен строго по `watchdog_bot/docs/RUNBOOK.md` (без локальных «обходов»).
- [ ] `.env` заполнен по канону форматирования (`/opt/standards/DOCS_CANON.md`, секции-разделители и порядок блоков).
- [ ] Проверены обязательные переменные (токен бота, LLM-ключ(и), admin password).
- [ ] При необходимости заполнены рекомендованные переменные (`OWNER_ID`, `TAVILY_API_KEY`, alerting/Grafana).
- [ ] Выполнена пересборка и запуск стека: `docker compose up -d --build`.
- [ ] Проведен живой smoke `/start` в Telegram.
- [ ] Проведен живой поисковый smoke (запрос, требующий web-search), ответ содержит отдельный блок `Sources`.
- [ ] Подтверждено корректное поведение по свежести: при отсутствии свежих данных бот честно указывает дату/ограничение.
- [ ] Проверены алерты и Grafana на стороне клиента (дашборд, contact point, базовые триггеры/доставка).
- [ ] Результаты smoke и проверок зафиксированы в отчете внедрения.

---

## 3) Передача — handoff клиенту (handoff checklist)

- [ ] Перед передачей выполнена ротация пароля админки.
- [ ] Клиенту переданы рабочие доступы (сервер, бот, админка, мониторинг) по безопасному каналу.
- [ ] Согласовано окно поддержки по выбранной редакции (SLA/режим коммуникации/эскалация).
- [ ] Передана памятка по ключевым командам бота (минимум: `/start`, сценарии поиска, служебные команды по роли).
- [ ] Переданы честные ограничения продукта:
  - portfolio/self-hosted формат (не enterprise SaaS из коробки);
  - зависимость от внешних API/баланса;
  - при отсутствии свежих данных бот не «выдумывает актуальность», а помечает ограничение.
- [ ] Клиент знает базовые шаги инцидентного старта: где runbook, как проверить логи, куда писать при деградации.
- [ ] Финальный акт handoff подтвержден обеими сторонами.
